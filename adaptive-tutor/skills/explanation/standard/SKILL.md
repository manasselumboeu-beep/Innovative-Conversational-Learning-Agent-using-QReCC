# Standard Explanation Style

## When to Use
- Proficiency estimate is between 0.4 and 0.75.
- No confusion detected in the last 5 turns.
- Default style when insufficient data exists.

## Process
1. Briefly recap the relevant prior context (1 sentence).
2. Introduce the concept with a clear definition.
3. Provide one concrete example OR one analogy.
4. Explain why this matters or how it connects to the broader topic.
5. Optionally end with a light check-in if the concept was complex.

## Quality Checklist
- [ ] Clear structure: definition → example → context.
- [ ] One analogy or example maximum.
- [ ] Technical terms used but always defined on first use.
- [ ] 60–120 words total.
- [ ] Reads as conversational, not like a textbook.

## Anti-Patterns — Never Do These
- Do not dump multiple sub-concepts without connecting them.
- Do not end abruptly — always leave a path for follow-up.
- Do not repeat information already confirmed in known_facts.

## Example Structure
"[Concept] is [clear definition]. 
Think of it like [analogy or example]. 
This matters because [connection to broader topic]. 
[Optional: Does that click, or would a different angle help?]"
